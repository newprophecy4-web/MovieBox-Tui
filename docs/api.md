# MovieBox HTTP API

The API is a headless HTTP layer over the repository's existing provider and resolver implementations. It does not host or store media. Run locally with `PORT=3000 cargo run --release --bin moviebox-api`.

## Configuration

| Variable | Meaning |
|---|---|
| `PORT` | Listening port supplied by Render; defaults to `3000` locally. The server binds to `0.0.0.0`. |
| `RUST_LOG` | Existing application log filter, for example `info`. |
| `ALLOWED_ORIGINS` | Comma-separated browser origins, for example `https://your-website.example,http://localhost:3000`. If omitted, development CORS is permissive. |

## Endpoints

- `GET /health` — fast provider-independent health check.
- `GET /api` — API index.
- `GET /api/v1/providers` — providers and capability flags.
- `GET /api/v1/search?q=naruto&provider=moviebox&page=1` — normalized real provider results. Query length is limited to 120 characters and results are capped at 50.
- `GET /api/v1/title/{id}` — normalized title metadata.
- `GET /api/v1/title/{id}/episodes?season=1` — seasons and episodes when the provider exposes them.
- `GET /api/v1/stream/{id}` — current release/mirror sources. Stream IDs identify provider, title, season, and episode; URLs are resolved at request time and are not persisted.

When `provider` is omitted from search, all configured providers are queried independently with an eight-second per-provider deadline. Successful providers contribute real results even if another provider fails or times out. An explicit `provider` query uses a ten-second deadline for that provider only. If every provider fails, the API returns a JSON `502` error.

Search result and title IDs are opaque URL-safe IDs returned by the API. Pass them back unchanged. Stream IDs are provider-specific opaque IDs generated by a future client from the provider/title/season/episode tuple; the current API deliberately does not expose arbitrary URL fetching.

## Errors

Errors are always JSON, for example:

```json
{"error":{"code":"INVALID_REQUEST","message":"Search query must be 1-120 characters"}}
```

Possible codes include `INVALID_REQUEST`, `NOT_FOUND`, `PROVIDER_ERROR`, `RESOLUTION_FAILED`, `UPSTREAM_ERROR`, and `RATE_LIMITED`.

## Examples

```sh
curl http://localhost:3000/health
curl http://localhost:3000/api/v1/providers
curl 'http://localhost:3000/api/v1/search?q=naruto'
```

## Render

Build command: `cargo build --release --locked`

Start command: `./target/release/moviebox-api`

Render supplies `PORT`; do not replace it with a fixed port. The health check path is `/health`. No terminal, media player, database, or interactive configuration is required.

The API exposes links to third-party provider sources rather than proxying or permanently storing media. Users are responsible for complying with applicable law and provider terms. Existing provider availability can vary by network, region, and upstream site status.
